# 驾驶沙盘高速旋转回正修复

2026-10-22。本次修复用于驾驶沙盘的意外腾空回正。99% 的目标尚未达到。

## 结果

冻结最终控制逻辑后，用整数 seed 20261024 生成 200 个初态，两版运行相同的 MuJoCo 模型、质量、气量、阀门延迟和接触标准。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 触地前回正 | 35/200，17.5% | 164/200，82% |
| 平稳落地 | 25/200，12.5% | 145/200，72.5% |
| 原来成功、修改后失败 | — | 0 |

回正指触地前至少一个 20 ms 采样点的倾角小于 10°、总角速度小于 0.5 rad/s。平稳落地继续使用现有驾驶判定，要求轮胎稳定支撑一秒，且没有车身碰撞或超限冲击。回正不等于安全落地。

这批样本覆盖均匀随机姿态、球面均匀旋转轴、2–12 rad/s 角速度、6–20 m 重心高度、−4 至 +5 m/s 竖直速度和 5 m/s 水平速度。所有样本均从 400 kg 满气、12 个喷嘴正常的状态开始，位于远离障碍的地面上方。失败样本全部计入。这是压力测试分布，不是实测玩家事故分布，不能直接推断实际玩家成功率。

原始数据为 [修改前](driving-recovery-baseline.json) 与 [修改后](driving-recovery-validation.json)，包含初态、逐例结果、参数及源代码哈希。前期用另一批 100 个初态开发，没有将其混入上述独立验证。

## 原因与改动

原控制器把横滚、俯仰、偏航合成一个力矩请求，再整体缩放。复合旋转样本 `[4, 8, 4] rad/s` 中，偏航请求约 82.1 kN·m，但对应方向只能输出 10 kN·m，三个力矩一起缩到约 12.2%。俯仰执行力矩只有约 12.5 kN·m，升力分配为零。油罐仍有气，并不说明这些喷嘴已经把可用力矩分配给旋转制动。

新增的 `driving-recovery.mjs` 只负责驾驶沙盘的意外腾空回正。

- 每次控制更新都根据当前姿态重新规划回正，避免碰撞后继续追逐旧路径的姿态点。
- 横滚或俯仰转速过高时先制动，降速后再回正。制动阶段不加入可能占满喷嘴能力的陀螺补偿；测试检查执行力矩对旋转做负功。
- 分别分配横滚/俯仰、升力、偏航，避免一个偏航极限同时压低其他方向的制动。刹降优先于航向调整。
- 车身接近水平后逐步对齐行驶方向，允许朝前或朝后落地，两个方向之间使用连续的偏航速度目标。

保留原有压力衰减、25 ms 阀门滞后、总喷力限制、质量与惯量变化、碰撞、补气时序、辅助开关及落地判定。没有设置车身姿态或直接修改角速度。用户主动触发的一圈翻转继续使用冻结的 v4 控制器，飞行实验与历史训练文件不变。

额外悬停等待偏航完成的开发方案增加了耗气并造成更多低压落地失败，最终代码没有采用它。

## 实际坡道

四条真实碰撞坡道分别以 −15°、0°、+15° 进入，速度 54 / 90 km/h，吸地风扇开 / 关，共 48 次。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 实际腾空 | 46 | 46 |
| 腾空期间曾达到回正标准 | 41 | 46 |
| 原有动作完成判定成功 | 26 | 31 |
| 从驶入开始全程没有车身或超限接触 | 0 | 0 |

原有驾驶程序在开始回正动作时清空此前的碰撞统计。因此，31 次动作成功不能解释为 31 次无碰撞通过。新增坡道测试从驶入开始累计碰撞；分段坡面的接触冲击在这些速度下会超过现有门槛。数据见 [坡道修改前](driving-ramp-recovery-baseline.json) 和 [坡道修改后](driving-ramp-recovery-validation.json)。

这组测试进一步说明，空中回正、平稳落地、全程安全通过是不同指标，不能拿 46/46 的中间结果宣称达到了 99%。

## 验证与复现

从项目的 `site` 目录运行：

```sh
node test-driving-recovery.mjs --baseline
node test-driving-recovery.mjs
node test-driving-ramp-recovery.mjs --baseline
node test-driving-ramp-recovery.mjs
```

旧版驾驶入口保存在 `backups/airborne-recovery-20261022/site/dist/`，基线测试读取该快照并复用未修改的物理依赖。

以下既有回归检查通过：`test-driving-assistance.mjs`、`test-experiments.mjs`、`test-driving-controls.mjs`、`test-driving-jump-cars.mjs`、`test-driving-worker.mjs`、`test-kickflip-debounce.mjs`、`test-driving-climb.mjs`。涵盖无喷嘴对照、关闭辅助、失败后保持物理姿态、连续翻转、5+2 秒补气、接地关气、继续驾驶、坡面吸附和物理异常处理。

新增检查覆盖高速制动力矩、喷嘴/总流量上限、气量为零、喷嘴全部禁用、空中四元数连续性、禁止空中补气，以及禁止把触边复位计作回正。

两种固定观测状态、各预热 50 次并测量 200 次的 Node 控制器耗时，p95 约 1.52–1.71 ms，最大 4.80 ms，没有超过 20 ms。详见 [计时数据](driving-recovery-timing.json)。这个测量不含物理积分、渲染、Worker 调度和手机性能。

## 99% 目标的剩余工作

独立验证仍有 55/200 个平稳落地失败，不能把它们全部认定为物理不可救。下一步需要区分剩余控制问题与高度、气压、喷嘴方向等限制，加入邻近坡面碰撞的预测，并在约定的玩家事故分布上重新验收。当前纵向预测仍针对水平地面，没有预测即将撞回坡侧的时间。

没有降低落地标准、增加喷嘴推力、无限补气或自动摆正来提高成功率。浏览器交互检查与数值压力测试分别验收。尚未完成实体手机性能验证或实车标定。
